# ContextOps — 디자인 브리프 v1.0 (Claude Design용)

> 사용 방법: 이 문서 전체를 Claude Design에 붙여넣고 "화면 1부터 순서대로 아트보드를 만들어라"고 지시한다. 각 화면의 콘텐츠는 아래에 적힌 실제 문구·수치를 그대로 쓴다(lorem 금지). 구현 스펙은 `docs/SPEC.md` §9와 대응한다.

---

## 1. 제품과 사용자

- **제품 한 줄:** 팀의 목표·로드맵·기술 결정을 하나의 승인된 AI Context로 만들어 모든 팀원의 Claude Code에 같은 버전으로 배포하고, 로드맵이 실제로 진행되는지를 근거와 함께 보여준다.
- **슬로건:** 팀의 기억과 AI의 기억을 한 방향으로. (2026-09-10 사용자 지시로 「팀의 지식과 Claude의 기억을 같은 방향으로」에서 바꿈 — 정본 `lib/web/site.ts`)
- **사용자 셋:**
  - 팀장(승인자) — 브라우저만. 가져오기 → 정리 → 발행, Roadmap 확인. 비개발자일 수 있음.
  - 개발자 — 명령 한 줄 설치 후 Claude Code 안에서 sync/propose. 웹은 가끔.
  - 심사위원(게스트) — 링크 열고 3분. 설치 없음. 첫 화면에서 문제를 10초 안에 이해해야 함.
- **감정 목표:** "감시 도구"가 아니라 "팀이 같은 방향을 보게 하는 도구". 사람이 결정하고 시스템이 보증한다는 느낌. 차분하고 정확한 개발자 도구, 화려하지 않음.

## 2. 디자인 원칙

1. **근거가 항상 옆에 있다.** 항목·문장·상태 옆에는 원문/코드 라인/커밋 링크가 붙는다. 근거 없는 숫자·판정은 화면에 없다.
2. **행은 마일스톤이지 사람이 아니다.** Roadmap의 기본 행은 마일스톤. 사람은 클릭해야 보인다. 개인 점수·순위·생산성 표현 금지.
3. **"실시간"이라는 말을 쓰지 않는다.** "마지막 보고: 8분 전, v1.3, applied" 형식.
4. **AI는 후보와 질문을 만든다.** AI 결과 카드는 항상 사람의 선택 버튼으로 끝난다. "AI가 판정했습니다" 같은 문구 금지.
5. **데모도 실제 상태를 숨기지 않는다.** loading/empty/error/오프라인/예산 소진 상태를 정직하게 표시.

### 테마 — **뉴트럴 모노크롬 한 벌 · 라이트 고정** (2026-09-10 · 같은 날 두 번째 판)

두 벌을 만들지 않는다는 원칙은 그대로다 — 벌이 **다크 → 웜 화이트 → 뉴트럴 모노크롬**으로 바뀌었을 뿐이다.
★ 왜 두 번째 판인가 — 웜 화이트 판을 실제 화면으로 찍어 보이자 사용자가 「색이 여전히 이상하고 AI 냄새가 심하다」고 했다.
원인은 **크림 바탕 + 남색 링크·막대 + 흙빛 초록·노랑·주황 칩**이 한 화면에 섞인 것이었다 (따뜻한 면 위의 차가운 색, 상태 칩의 색 면 다섯 종).
같은 실제 화면(랜딩·Context·정리)에 색 처리만 다른 셋(뉴트럴 모노크롬 · 웜+점 · 쿨그레이+주황)을 덮어 찍어 보였고 사용자가 뉴트럴을 골랐다
(`docs/evidence/2026-09-10-redesign/variants/`). **색은 이제 상태의 점·기호에만 있다** — 칩에 색 배경이 없다.
★ 왜 바꿨나 — 사용자가 배포된 화면을 보고 「AI 느낌이 강하고 개성이 없다」고 했다 (2026-09-10).
검은 바탕 · 파란 버튼 · 회색 카드 · 고딕 600 표제 · 3열 같은 카드는 이 시기 AI 가 만드는 개발자 도구의
**기본값**이라, 제품이 무엇인지 말하기 전에 「또 그거」로 읽힌다. 참고로 준 것은 buildwithtaste.com 이고,
그 서비스의 MCP(`https://mcp.buildwithtaste.com/mcp` · OAuth · 읽기 전용)를 연결해 **anti-slop 지침**을 받았다
(`docs/evidence/2026-09-10-redesign/taste-anti-slop.md` 에 원문). 사용자 계정에 저장된 샘플·프로필은 아직 없어
그 지침이 이번 벌의 근거다. 후보 넷(웜 미니멀 · 블루프린트 · 스위스 · 관제실)을 같은 문구로 렌더해 보였고
「추천해 달라」에 웜 미니멀을 골랐다.

**이 벌이 지키는 anti-slop 규칙** (지침 → 우리 자리):
- 파란 주요색 금지 → 주요 액션은 **검정 알약** 하나. 링크·포커스도 잉크(`accent-ink` = `ink`) — 색 있는 링크가 곧 「기본값」이다.
- gray-50 바탕 금지 → 순백 바탕 위에 회색 **괘선**만. 면을 색으로 나누지 않고 선으로 나눈다 (Linear·Vercel 의 결).
- **상태 칩에 색 배경 금지** → 칩은 투명·잉크 글자이고 **색점(CSS 원 · `.chip-dot`)만** 상태색이다. 특수문자 아이콘(✓ ● § ¶ …)은 쓰지 않는다 (2026-09-10 저녁 · 사용자: 「이런 특수문자들이 마음에 안 든다」).
  ★ 왜 — 초록·노랑·주황 면이 표마다 수십 개 서면 그게 「관리자 템플릿」의 얼굴이다. 상태는 라벨 글자가 말한다.
- Inter 단독 금지 → 본문 Pretendard 에 **표제체 IBM Plex Sans KR** 을 짝지었다. 층마다 굵기가 다르다(h1·h2 600 표제체 · h3·h4 700 본문체).
- 큰 글자는 자간을 좁히고(-0.02em) 작은 글자는 넓힌다(라벨 +0.3px) · 표제 행간 1.2 · 본문 1.55.
- 3열 같은 카드 금지 → 「왜 git」은 **정의 목록**(5/7 비대칭) · 「어떻게」는 번호 목록 · 제품 화면은 **2×2 네 장**(코스의 네 걸음 · 카드 없이 그림 + 번호 동그라미 · 2026-09-10 저녁).
- 가운데 정렬 금지(의도한 순간만) → 전부 왼쪽 정렬. 히어로도 7/5 비대칭.
- 절마다 같은 여백 금지 → 절 사이 간격이 다르다(`landing.module.css`).
- 스크롤 fade-up·타자 효과·숫자 세기 금지 → 움직이는 것은 터미널 **녹화 재생**과 진행 막대뿐(둘 다 내용이다).
- 아이콘-원-제목-문단 카드 금지 → 아이콘 없음. 글과 괘선으로만.
- 「craft 신호」 → `::selection` 을 우리 색으로 · 표제 `text-wrap: balance` · 링크 밑줄 offset/두께 · `tabular-nums` · `prefers-reduced-motion`.
색은 상태(ok/warn/bad)와 AI 산출물(llm)에만 쓴다. 개성은 색이 아니라 **표제의 크기·자간·여백·진짜 화면**에서 온다.
⚠ 다크 모드는 만들지 않는다 (같은 이유 — 두 벌은 둘 다 어중간해진다). `layout.tsx` 는 `color-scheme: light` 다.
(`docs/KNOWN_LIMITATIONS.md` 에 적혀 있다.)

- **상태를 색만으로 구분하지 않는다** — 라벨 글자가 상태를 말하고 색점은 거들 뿐이다 (특수문자 아이콘 없음 · 2026-09-10 저녁).
  ★ 왜 — 색각 이상뿐 아니라, 발표 영상·인쇄된 심사 자료에서 색이 뭉갠다.
- `accent` 는 **한 화면에 주요 액션 하나**에만. 보조 버튼은 outline(흰 알약 + `line-hi`).
  ★ 왜 검정인가 — 색이 있는 버튼은 그 색이 곧 「브랜드」가 되고, 그게 이 시기 AI 산출물의 파란 버튼이었다.
  검정 하나면 화면의 색은 전부 **상태**의 것이 된다.
- `on-accent` 는 accent 위의 글자다. ★ 왜 — `ink` 가 검정이 된 뒤로 버튼 글자를 `ink` 로 그리면 안 보인다 (다크 시절의 습관).
- `sand` 는 **띠**다 — 프롬프트 줄·드래그 선택처럼 「여기부터 여기까지」를 말하는 자리. 값은 `surface-hi` 와 같지만 뜻이 다르다 — 갈라 쓸 날을 위해 이름을 남긴다.
- `ok`·`warn`·`bad`·`llm` 은 **점·기호·짧은 라벨**에만 쓴다. 면(`*-bg`)은 제안 diff 의 줄 배경에만 남았다 — 칩에 되살리지 마라.
- `term-*` 셋은 **터미널 재생·설치 명령 블록**만 쓴다. 오프화이트 위에 검은 상자 하나가 「기계가 말하는 자리」다 —
  다른 어두운 면을 만들지 마라. 만들면 한 벌이 아니라 다크 모드 조각이 된다.
- `llm` 은 **AI 산출물에만.** 사람이 정한 것에 이 색이 붙으면 신뢰 경계가 흐려진다.
- 🔴 **`ink-4` 로 읽어야 하는 글자를 그리지 않는다** — 용도가 「비활성」 한 낱말인 이유다.
  비활성 상태(`:disabled`)와 장식(`aria-hidden` 인 `◌`·빈 칸 `—`)에만 쓰고,
  **읽어야 하는 보조 글자는 `ink-3`(`meta`)** 로 그린다.
  ★ 왜 — 흰 카드 위 대비가 2.0:1 이라 발표 영상·인쇄된 심사 자료에서 **글자가 없는 것과 같다.**
  다크 시절에 실제로 다섯 자리가 이 색으로 쌓였고 그중 둘은 제품의 주장 그 자체였다 (FINDINGS 88).
  이것도 `design-tokens.test.ts` 가 잠근다.
- 대비는 전부 잰 값이다 (2026-09-10 · WCAG 상대 휘도 · 흰 바탕): 본문 `ink-2` 10.4:1 · 메타 `ink-3` 5.3:1(surface-hi 위 4.8) · 잉크 링크 19.9:1 ·
  상태 글자 ok 4.7 · warn 4.9 · bad 5.9 · llm 5.1 · `on-accent`/`accent` 19.6 · 터미널 `term-ink-2`/`term-bg` 8.6. 전부 AA(4.5) 위다.
  값을 옮기면 다시 재라 — 흰 바탕에서 채도 높은 상태색은 금방 4.5 아래로 떨어진다 (green-600 은 3.3 이라 700 을 썼다).
- 🔴 **이 표는 기계가 잠근다.** `apps/web/src/app/globals.css` 의 `:root` 가 이 표와
  **정확히 같아야** 하고, `apps/web/test/design-tokens.test.ts` 가 양쪽을 대조한다.
  화면 코드에 색 리터럴(`#…`·`rgb(`)을 적으면 그 시험이 빨개진다.
  ★ 왜 — 「토큰만 쓴다」는 문서에 적어 두면 반드시 어느 화면 하나가 즉석 색을 찍는다.
  게이트는 문서보다 강하다 (`CLAUDE.md` 「같은 지적이 두 번 나오면 게이트로 올려라」).
  ⚠ `bad-bg` 는 이 표에 없었는데 화면 5·7 의 `bad` 칩이 필요해서 **여기에 먼저 더하고**
  썼다 — ok/warn 에만 배경이 있으면 같은 칩이 상태에 따라 다른 모양이 된다.
  `sand`·`on-accent`·`term-*` 도 같은 길로 들어왔다 (2026-09-10). 값이 같은 토큰 둘(`bg`=`surface` · `sand`=`surface-hi` · `accent`=`ink`=`accent-ink`)은
  **뜻이 달라서** 따로 있다 — 나중에 갈라 쓸 때 화면을 안 고치려고.

### 타이포

### 접근성

- **키보드 포커스는 보여야 한다**: `:focus-visible { outline: 2px solid var(--accent-ink); outline-offset: 2px }`
  **한 곳**(`globals.css`) — 버튼·링크·입력·행·탭이 전부 그 한 줄을 읽는다. `outline: none` 은 어디에도 쓰지 않는다.
  ★ 왜 — 탭으로 훑는 사람에게 「지금 어디인가」가 없으면 화면이 없는 것과 같다. Linear·Stripe·GitHub 전부 또렷한
  링이 있고, 심사에서 키보드로 훑는 사람이 있으면 바로 보인다 (FINDINGS 130 · 사람이 잰 것: `:focus-visible` 0개 ·
  `outline: none` 1개). `:focus` 가 아니라 `:focus-visible` 인 이유 — 마우스 클릭엔 안 뜨고 키보드에만 뜬다.
  그래서 아무도 지우고 싶어지지 않는다.
  가로 스크롤 컨테이너 안의 폭 100% 행(Pack 줄)은 바깥 링이 잘려서 `outline-offset: -2px` 로 안쪽에 그린다.
- **움직임을 줄여 달라면 줄인다**: `@media (prefers-reduced-motion: reduce)` 블록 **한 곳**(`globals.css`)이
  `*, *::before, *::after` 의 `animation-duration: 0.01ms` · `animation-iteration-count: 1` ·
  `transition-duration: 0.01ms` · `scroll-behavior: auto` 를 `!important` 로 준다.
  ★ 왜 한 곳인가 — 조각마다 적으면 새로 움직이는 것이 하나 생길 때마다 반드시 하나를 빠뜨린다.
  여기 한 블록은 **아직 없는 애니메이션까지** 덮는다 (FINDINGS 134 · INBOX 2026-09-06 🟡 D).
  `!important` 를 쓰는 자리는 이 블록뿐이다 — 취향이 아니라 뒤의 어떤 규칙보다도 세야 하는 **끄는 스위치**다.
  `none` 이 아니라 `0.01ms` 인 이유 — `none` 은 재생 중이던 것을 시작 상태로 되돌린다.
  **CSS 로 못 끄는 움직임은 JS 가 같은 질의를 읽는다**: 랜딩의 터미널 재생은
  `matchMedia('(prefers-reduced-motion: reduce)')` 가 참이면 재생하지 않고 마지막 프레임을 그대로 둔다.
- 상태를 색만으로 구분하지 않는다 (위 「색」 절) · 대비는 본문 9.1 : 1 · 메타 5.3 : 1 (WCAG AA 4.5 를 넘는다 · 2026-09-10 웜 화이트로 다시 잼 — 표는 「색」 절 끝).

🔴 **실패한 구조화에는 [다시 시도] 가 붙는다 — 단, 붙는 실패와 안 붙는 실패가 있다** (FINDINGS 59).

**다시 불러도 같은 자리에서 죽는** 실패에는 안 붙는다 — 그 버튼은 LLM 을 한 번 더 부르는 버튼이라

- 🔴 **「멈춘 것 같음」(`stalled`)에도 [다시 시도] 가 붙는다 — 단 하는 일이 다르다** (FINDINGS 154).
  그 행은 `running` 이라 되돌리면 아직 살아 있을지 모르는 러너와 둘이 같은 job 을 굴린다.
  그래서 서버는 그 행을 **실패로 닫고 같은 문서로 일을 새로 만든다.** 버튼 옆 문장도 그래서 다르다:
  `멈춘 작업은 실패로 기록하고, 같은 문서로 새 작업을 시작합니다. 문서를 다시 올릴 필요는 없습니다.`(글자의 정본은 `job-progress.tsx` 의 `RETRY_NOTE.fresh`)

    `jobRetryMode()` 가 읽고, 문장은 그 갈래를 키로 하는 `RETRY_NOTE` 에서 온다.
  - ⚠ **도는 중인(멈추지 않은) job 에는 버튼이 없다.** 있으면 사람이 멀쩡한 일을 죽인다.

  ⚠ 서버가 **이름**을 낸다(`users` 를 작성자·결정자로 두 번 join) — uuid 를 그리지 않고, 사람을 못 찾으면 `—` 다. 지어내지 않는다.
- 예시 데이터: `카카오 API 검증 상태 갱신` — before `- 카카오 실제 API 응답은 아직 확인하지 못했다.` after `+ 2026-08-04 실제 API 검색 10권을 검증했다.` `+ 응답 ISBN은 13자리로 확인했다.` `+ 분야 정보는 제공되지 않는다.` 근거 `북스택 QC결과.md L12–19 · src/search/kakao.ts:88`.

## 5. 상태·오류 문구 (그대로 사용)
- loading: skeleton, 문구 없음.
- 🔴 **empty 의 문구와 「다음 행동」의 정본은 표 하나다** — `apps/web/src/lib/web/screens.ts` 의
  `EMPTY_PLACES` (FINDINGS 133). 빈 상태를 그리는 자리는 `ScreenEmpty` 하나이고, 화면은 자리 이름만 말한다.
  ★ 왜 — 「항목이 없습니다」에서 갈 곳이 없으면 첫 사용자가 거기서 막힌다. 화면마다 손으로 적으면
  **한 화면만 버튼이 없는 채로** 남고, 비어 있을 뿐 멀쩡해 보인다.
  ⚠ 갈 곳이 화면 밖(CLI·같은 화면의 다른 칸)이면 버튼을 만들지 말고 `noNext` 에 이유를 적는다 —
  **아무 데도 안 가는 버튼**을 두지 않는다 (FINDINGS 117 과 같은 뿌리).
  ⚠ 목적지는 `PROJECT_SCREENS` 의 `path` 여야 한다 (404 로 가는 버튼 0개 · `test/web-empty-states.test.ts`).
- empty(Context): `아직 항목이 없습니다. 가져오기에서 문서를 올리거나 질문에 답해보세요.`
- 409(항목 수정): `다른 사람이 먼저 수정했습니다. 최신 내용을 불러왔어요. 다시 저장해주세요.`
- 403(게스트 · 읽기 전용): `읽기 전용으로 둘러보는 중입니다. 바꾸려면 내 팀으로 시작해야 합니다.` + [내 팀으로 시작하기]
  🔴 게스트에게 「이 작업은 팀장만 할 수 있습니다」(member 의 403)는 **거짓말**이다 — 로그인해도 샘플 팀에서는 못 한다 (FINDINGS 121).
  문구의 자리는 `lib/web/api.ts` 의 `GUEST_HINT`(게스트일 때만 덮는 표 · `ERROR_HINT` 는 코드당 하나 그대로).
  🔴 **쓰기 버튼은 누르기 전에 서버와 같은 표(`ACTOR_RULES.writes`)를 읽는다** — 게스트가 [발행하기] 를 누르면 모달이 아니라
  이 문장이 버튼 밑에 뜬다 (`ReadOnlyNotice` · `role="status"` · FINDINGS 135). 버튼을 숨기지는 않는다 — 막는 것은 서버다.
- 발행 실패: `발행이 취소되었습니다. 항목 item_bs_m2 (roadmap)의 done_when이 비어 있습니다.` [항목 열기]
- 오프라인/보고 없음: `아직 보고가 없습니다` (never "offline").
- 예산 소진: `AI 예산이 소진되었습니다. 하루 상한이면 내일, 한 달 상한이면 다음 달에 다시 시도해주세요.`
  🔴 원래는 `샘플 결과를 표시합니다.` 였다 — **표시하는 코드가 0곳이었다** (FINDINGS 66).
  화면은 없는 것을 약속하지 않는다. 픽스처로 떨어지는 갈래는 **어디에도 없다** (§7.4 의 `/demo/ai-once` 도 없다 · INBOX G9 —
  키 없는 배포는 `AI_NOT_CONFIGURED` 「AI 기능이 아직 설정되지 않았습니다. 운영자에게 알려주세요.」). 되살리려면 **문구가 아니라 코드가 먼저**다.
