## 결론 — 161 이 적어 둔 원인 짐작이 **틀렸다**

161 은 「폰트 래스터·타이밍으로 보인다(아직 안 쟀다)」고 적었다. **아니다.**

- `screen-sync` 가 두 관통에서 **바이트까지 똑같다.** 캡처(폰트 래스터·PNG 인코더)는
  **결정론적**이다. 인코딩 잡음이라면 이 장도 흔들렸어야 한다.
- 달라진 자리는 그림 전체가 아니라 **글자 몇 개**다. 잘라서 눈으로 읽었다
  (`crop-*.png`): 달라진 것은 **`manifest_hash` 와 발행 시각**이다.
  - `crop-context-committed.png` `d3585389` ↔ `crop-context-fresh.png` `0d9a5f49`
  - `crop-packs-committed.png` `d3585389`·`7fe9fe52` / `2026-09-07 02:39`
    ↔ `crop-packs-fresh.png` `0d9a5f49`·`acd8c666` / `2026-09-07 03:15`

즉 **그림은 낡지 않았다. 데모가 매 관통마다 다시 심겨서 다른 Pack 이 나온 것**이다.

왜 다른 Pack 이 나오나 — Pack 의 모든 줄에 붙는 역추적 태그가 문서 **버전 uuid** 를 싣는다
(`<!-- ctx:item_… src:doc:fcba7932-…#260-311 -->`). 그 uuid 는 DB 가 심을 때마다 새로 나므로
**본문 바이트가 달라지고 → `manifest_hash` 가 달라진다.** 발행 시각(`published_at`)은 심는 시각이다.

⚠ **P4 위반이 아니다.** P4 는 「같은 snapshot → byte-identical Pack」이고, 여기서는
snapshot 자체가 다르다(항목의 `source_refs` 안 uuid 가 다르다). 컴파일러는 결정론적이다.

## 이번 바퀴가 한 것 · 남은 것

- **한 것**: `shotcopy` 가 옮기기 전에 **픽셀로 견주고**, 한 픽셀도 안 달라졌으면 **안 옮긴다.**
  달라졌으면 몇 픽셀이 어느 줄에서 달라졌는지를 관통 로그에 **매 바퀴 찍는다** —
  「매 바퀴 그림이 바뀐다」가 더는 짐작이 아니다.
- **남은 것**: 데모 씨앗이 매번 다른 문서 버전 uuid 와 다른 시각을 쓰는 한
  `screen-context`·`screen-packs` 두 장은 **계속 달라진다** (그림이 진짜로 달라지므로
  위 게이트도 옳게 옮긴다). 그걸 없애려면 **데모 씨앗을 재현 가능하게** 만들어야 한다
  (고정 시계 + 결정론적 문서 버전 id). 161 에 그렇게 적었다.
