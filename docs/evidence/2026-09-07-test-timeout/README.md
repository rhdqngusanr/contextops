## 무엇을 기다리나 — 파일 I/O 가 아니라 **자식 프로세스 기동**이다

빨개진 두 시험(`plugin/contextops/test/hooks.test.ts`)은 훅 스크립트를 **진짜로 띄운다**:

- `execFileSync('git', ['init', '-q'])` — 자식 프로세스 1
- `execFile(process.execPath, [scripts/stop.mjs])` — 자식 프로세스 2 (node 부팅)

번들이 아니라 Claude Code 가 `node <경로>` 로 그대로 부르는 파일이라 프로세스로 재야 한다
(그 파일 머리 주석). 즉 이 시험이 기다리는 것은 **프로세스 기동 시간**이다.

잰 한가함 최악(190ms)의 **26배 이상**이었다는 것만 안다. 136 이 같은 기계에서 잰 훅의
부하 배율(2~3초 → 17~18초 · 6~9배)로는 5초를 못 넘기는데 넘겼다 — 프로세스 기동은 부하에서
wasm 기동보다 **더 나쁘게** 는다. 그래서 관측된 실패(5초)의 **6배**로 잡는다.

상한은 **실패 판정선만 옮기고 정상 속도는 그대로다.** 「영원히 안 끝남」과 「느리다」는 여전히 갈린다.
