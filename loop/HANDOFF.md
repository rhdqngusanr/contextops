### 🔴 루프를 다시 켰다 — 일을 고르기 전에 **멈출지부터** 판단한다 (2026-09-15 기준)

루프는 2026-09-07 밤부터 `loop/STOP` 으로 멈춰 있었고, 그 뒤 작업은 사람이 연 Claude Code 세션이 했다.
그사이 바뀐 사실 셋:

- **production 이 떠 있다** — <https://contextops-rosy.vercel.app> 은 `main` 에서 배포된다
- **대회 과제는 2026-09-14 에 제출됐다** — 9/20 23:59:59 까지 고칠 수 있고, 9/21~10/5 심사 기간에
  링크가 안 열리면 제외될 수 있다. 사람이 9/18 에 `release` 브랜치로 동결할 계획이다
- **`loop/env.ps1` 이 `AutoPush = $true` · `Branch = "main"` 이다** — 커밋이 생긴 바퀴마다
  `loop.ps1` 이 `git push origin main` 을 하고, 그 push 가 production 을 다시 배포한다

#### 0순위 — 사람의 결정이 적혀 있나

이 블록이나 `docs/feedback/INBOX.md` 에 사람이 「심사 기간에 `main` 에서 루프를 돌린다」고 적어 두지 않았다면
**어떤 파일도 고치거나 커밋하지 마라** (`docs/STATUS.md` 도 — 커밋은 곧 push 다).
`loop/STOP` 파일만 만들고(`.gitignore` 대상이라 커밋이 안 생긴다) 무엇을 봤는지 마지막 답에 한 줄 남기고 끝낸다.
루프는 이 바퀴가 끝나면 STOP 을 보고 멈춘다.

★ 왜 — 이 바퀴의 커밋 하나가 심사 중인 production 을 사람 확인 없이 다시 배포한다.
⛔ `Branch`·`AutoPush` 를 루프가 스스로 바꾸지 마라 — 그것도 사람이 정한다.

#### 결정이 있으면 — 고르는 순서 (`loop/PROMPT.md` ④3 · 2026-09-05 규칙)

1. `docs/feedback/FINDINGS.md` 에서 ✅ 가 안 붙은 **`[고장]`**(진행이 막히는 것 — 관통 FAIL · CI RED · 500 응답)이
   있으면 그것부터. PLAN 보다 위다
2. 없으면 `docs/PLAN.md` 의 `- [ ]` **맨 위 행**. `[구멍]`·`[격차]` 는 PLAN 을 막지 않는다 — 대장에 적어만 둔다
3. PLAN 이 다 닫혔으면 FINDINGS 맨 위 (구멍 → 격차)

⚠ 지금 열린 PLAN 행 셋(P5 「Vercel production · Cron · 보안 캡처 증거 · 새 PC fresh install」 · P6 「2분 영상 ·
슬라이드 · 리허설」 · P6 「제출서 · README · KNOWN_LIMITATIONS」)은 **남은 몫이 전부 🙋 사람 몫이다.**
루프가 할 수 있는 것이 없으면 억지로 만들지 말고 「막힌 것」에 적고 멈춰라.
⛔ 할 일이 떨어졌다고 멀쩡한 코드를 리팩터링하지 마라. 그게 자율 루프의 최대 실패 모드다.

#### 결정이 있어도 그대로인 울타리

- ⛔ **`loop/`·`tools/` 를 P2 위반으로 지우지 마라** — 그게 이 루프 자신이다
- 🙋 사람만 할 수 있는 것: 계정·키가 필요한 일(Vercel · Supabase · GitHub · 도메인 · API 키) · 녹화 · 대회 제출 ·
  동결 · 실데이터 픽스처 공개 여부 판단. 루프는 **코드와 설정 파일까지만** 하고 `docs/STATUS.md` 「막힌 것」에 적고 멈춘다
- 🙋 판단이 안 서는 제품 결정(semver 정책 변경 · 원칙 완화)은 **추측하지 말고 건너뛰고**
  「막힌 것」에 적는다
