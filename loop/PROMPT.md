# 한 바퀴 지시서

> 이 파일이 한 바퀴의 전부다. 세션은 매 바퀴 **새로** 열리고, 이전 대화를 하나도
> 기억하지 못한다. 네가 아는 것은 이 파일과, 여기서 읽으라고 한 문서뿐이다.
>
> 기억은 대화가 아니라 **파일**에 산다. 그래서 마지막에 `docs/STATUS.md` 를 갱신하는 게
> 이 바퀴에서 제일 중요한 일이다 — 그걸 안 쓰면 다음 바퀴는 아무것도 모르는 채로 시작한다.

---

## ① 합격 기준

```
① 절대 원칙 P1~P7 을 하나라도 깨면 그 바퀴는 실패다.
② 테스트 초록은 「안 죽었다」지 「된다」가 아니다. 관통 시나리오가 돌아야 된 것이다.
③ 화면은 캡처를 직접 눈으로 보고 판정한다. 컴파일 초록은 최소선이다.
```

통과 못 한 것은 **커밋하지 말고** `docs/STATUS.md` 의 「눈 판정 대기」에 근거와 함께 적어라.
어중간한 걸 올리면 다음 바퀴가 그 위에 쌓는다.

### 🔴 P1~P7 이 이 제품의 전부다 (`docs/SPEC.md` §0.1)

| # | 원칙 | 어기면 |
|---|---|---|
| P1 | 서버는 **코드 본문·secret·개인 Memory·대화 transcript를 절대 받지 않는다** | 제품의 유일한 방어선이 무너진다. 심사에서 첫 질문이 이거다 |
| P2 | 우리 **제품 코드**는 사용자의 Claude를 대신 호출하지 않는다 | 구독 재사용은 정책 위반이고, 잡히면 실격이다 |
| P3 | 서버측 LLM은 API 키로만, 4개 기능 한정, 예산 가드 필수 | 하룻밤에 예산이 다 탄다 |
| P4 | **승인 이후 파이프라인에는 LLM이 없다.** 같은 snapshot → byte-identical Pack | 재현이 안 되면 「같은 버전·같은 해시로 배포」라는 주장이 거짓이 된다 |
| P5 | 진행 상태는 **마일스톤 단위만.** 개인 생산성 점수·순위 금지 | 「감시 도구」가 되는 순간 아무도 안 쓴다 |
| P6 | Hook은 파일을 변경하지 않는다 | 사용자 저장소를 몰래 고치는 도구가 된다 |
| P7 | 모든 Pack 줄은 항목 ID → 원문으로 **역추적**된다 | 근거 없는 줄이 하나라도 있으면 「환각 차단」 주장이 무너진다 |

### ⛔ P2 의 경계 — `loop/` 와 `tools/` 는 예외다. 지우지 마라

**이 루프 자신이 `claude -p` 로 돈다.** P2 가 금지하는 것은 **우리가 배포하는 제품 코드**
(`plugin/` · `packages/` · `apps/`)가 **사용자의** Claude 구독을 대신 호출하는 것이다.
`loop/` 와 `tools/` 는 **우리가 이 저장소를 만드는 개발 도구**이고, 우리 자신의 구독을 쓴다.

⚠ **이걸 헷갈려서 `loop/loop.ps1` 을 「P2 위반」이라고 지우지 마라.** 지우면 다음 바퀴가
없다. `tools/principles.ps1` 의 P2 검사도 `loop/`·`tools/`·`docs/` 를 제외하고 센다.

## ② 먼저 읽을 문서

**정본은 `docs/SPEC.md` 다.** 무엇을 만들 것인가는 거기서 시작한다. 크니까 통째로 읽지 말고
**색인이 지목하는 § 만** 읽어라.

> 🔴 **그러나 SPEC 을 「현실」로 믿지 마라.** SPEC 은 **의도**의 정본이고
> **코드가 현실**이다. SPEC 에 적힌 함수·필드·엔드포인트를 근거로 삼기 전에
> **코드에서 그 이름을 찾아 실제로 존재하는지 확인해라.** 안 그러면 없는 것 위에 짓는다.
>
> SPEC 과 코드가 다르면: **무엇을 만들지는 SPEC**, **무엇이 지금 도는지는 코드.**
> 둘의 차이를 발견하면 `docs/feedback/FINDINGS.md` 에 적어라 — 그게 다음 바퀴의 일이다.

| 순서 | 파일 | 읽을 범위 | 왜 읽나 |
|---|---|---|---|
| 1 | `docs/feedback/INBOX.md` | 전체 | **사용자 지시가 최우선이다.** 여기 뭐가 있으면 그게 이번 바퀴의 일이다 |
| 2 | **`docs/feedback/FINDINGS.md`** | 「다음에 고칠 것」 | 관통이 찾아 놓은 목록. ⚠ **여기서 일을 고르는 건 `고장`뿐이다** — `구멍`·`격차`는 PLAN 을 막지 않는다 (④3) |
| 3 | `CLAUDE.md` | 전체 (짧다) | 저장소 작업 규칙 |
| 4 | `docs/STATUS.md` | 전체 | 어디까지 했고 다음이 뭔가 · 막힌 것 |
| 5 | **`docs/PLAN.md`** | `- [ ]` 맨 위 행 | 🔴 **고장이 없으면 이번 바퀴의 일은 여기 있다** (④3). 제출일이 있는 프로젝트다 |
| 6 | 아래 색인이 지목하는 `docs/SPEC.md` § | 해당 § 만 | **이번에 건드리는 것의 정본** |

> 🔴 **2번(FINDINGS)을 건너뛰지 마라.** rift 에서 이 줄이 없어서 루프가 **자기가 쓴 목록을
> 안 읽었다.** 다음 할 일을 매번 로드맵에서 새로 골랐고, 어제 찾아 놓은 고장은 영원히 남았다.
> **쓰기만 하고 읽지 않는 파일은 없는 파일과 같다.**

## ③ 규칙과 근거

> 금지만 적으면 빠져나갈 길을 찾는다. **이유를 적으면 그 이유를 지킨다.**
> 규칙을 더할 때는 반드시 "왜" 를 같이 적어라.

| 규칙 | 왜 |
|---|---|
| **SPEC 은 의도, 코드는 현실.** 둘이 다르면 무엇을 만들지는 SPEC, 무엇이 도는지는 코드 | 문서에 있는데 구현이 없거나, 정의는 있는데 아무도 안 읽는 코드가 이런 저장소의 단골 고장이다. 「문서가 맞다」로만 두면 없는 것 위에 짓는다 |
| **모든 외부 입력은 `packages/schema` 로 파싱한다.** 새 필드는 스키마에 먼저 | P1 이 스키마 하나에 걸려 있다. 라우트마다 손으로 검사하면 한 곳만 빠져도 방어선이 뚫린다 |
| **`packages/compiler` 는 순수 함수만.** `Date.now`·`Math.random`·네트워크 금지 | P4 = 「같은 snapshot → byte-identical Pack」. 시각 하나만 섞여도 golden test 가 매일 빨개지고, 재현성 주장이 거짓이 된다 |
| **golden test 를 깨면 템플릿 버전을 올리고, expected 를 갱신한 이유를 커밋 메시지에 쓴다** | 아무 말 없이 expected 를 덮으면 게이트가 게이트가 아니게 된다. 「테스트가 빨개서 테스트를 고쳤다」가 제일 흔한 자멸이다 |
| **표를 만들면 「표의 항목이 전부 실제로 뭔가를 바꾼다」를 시험으로 잠가라** | 10종 중 8종이 무효인데 화면에는 멀쩡히 뜨는 종류의 고장은 **눈으로 절대 안 잡힌다.** ItemType 10종·에러 코드 9종·상태 5종이 전부 이 위험에 있다 |
| **서버 AI 호출은 `withBudget()` 경유 외에 금지** | P3. 한 곳만 새도 하룻밤에 예산이 탄다. 그리고 새는 자리는 항상 「급해서 임시로」 부른 자리다 |
| **로그에 body·토큰·문서 본문을 남기지 않는다** (`request_id`·route·status·latency만) | P1 은 「받지 않는다」이지 「받아서 안 쓴다」가 아니다. 로그에 남으면 이미 받은 것이다 |
| 🔴 **확장은 「표에 한 줄」이어야 한다.** 타입별 분기를 여러 파일에 흩지 말고 표 하나로 모으고, 화면·컴파일러는 그 표를 **읽기만** 한다. 더하는 절차는 그 표 옆 주석에 | **오픈소스로 공개한다 — 남이 읽고 남이 한 줄 더한다.** 판정 기준은 「ItemType 을 하나 더하려면 몇 군데를 고쳐야 하나」다. 절차가 코드 밖에 있으면 다음 사람은 반드시 하나를 빠뜨린다 (사용자 상시 지시 · 상세는 `CLAUDE.md`) |
| **경계에만 인터페이스. 사용자가 하나뿐이면 만들지 마라** | 과설계는 확장성이 아니라 **확장을 막는다.** 하나뿐인 구현을 위한 추상은 둘째가 왔을 때 안 맞아서 결국 다시 짠다. 둘째가 생기면 그때 올린다 |
| **의존 방향은 한쪽으로** (`schema ← compiler ← web/plugin`) · 패키지는 `index.ts` 로만 내보낸다 | 스키마가 웹을 import 하면 끝이다. 내부를 직접 import 하기 시작하면 리팩터링이 불가능해진다 |
| **한 바퀴에 하나만 만진다** | 둘을 건드리면 실패했을 때 어느 쪽이 원인인지 못 가린다. 무인이라 물어볼 사람도 없다 |
| **`git add .` 금지 — 경로로 담고, 담기 전에 `git status --short`** | 여러 세션이 이 디렉터리를 공유한다. 남의 미완성 작업을 같이 커밋하면 되돌리기 어렵다 |
| **셸 명령을 `;` 나 `&&` 로 이어 붙이지 마라 — 한 번에 하나씩** | 🔴 무인 세션은 `bypassPermissions` 로 도는데도 **여러 명령을 이어 붙이면 거부된다.** rift 의 첫 바퀴가 `git status; git log` 한 줄 때문에 두 번 거부당하고 69초 만에 끝났다. **조용히 막히는 종류라 로그를 안 보면 모른다** |
| **PowerShell 은 5.1 이다.** `&&`·`??`·삼항 연산자 없음. `2>&1` 을 네이티브 exe 에 쓰지 마라 | PS 5.1 은 네이티브 stderr 를 ErrorRecord 로 감싸서 **exit 0 인데도 `$?` 가 `$false` 가 된다.** git 호출이 이유 없이 실패한 것처럼 보인다 |
| **`.ps1` 은 UTF-8 **BOM 있음**으로 쓴다** | BOM 이 없으면 PS 5.1 이 ANSI 로 읽어 **한글 주석·문자열이 깨진다.** 깨진 문자가 문자열 안에 있으면 조용히 잘못 동작한다 |
| **수치를 하드코딩하지 마라** — 상수를 참조한다 | 같은 값이 여러 군데 생기면 한쪽만 고쳐지고 조용히 갈라진다 |
| **`loop/`·`tools/` 를 「P2 위반」으로 지우지 마라** | 그게 이 루프 자신이다. ① 의 경계 설명을 읽어라 |

## ④ 한 바퀴 도는 순서 — **먼저 관통시켜 보고, 그 다음에 고친다**

> ★ 왜 이 순서인가 — `STATUS.md` 의 목록에서만 고르면 **목록에 없는 고장은 영원히
> 안 보인다.** rift 에서 「첫 전투 뒤 진행 불가」가 목록 어디에도 없었고 스모크도 초록이었다.
> 사람이 한 판 해 보고 나서야 나왔다. **목록은 관통이 만든다.**

### 0. 아직 관통할 게 없으면 (P0~P1 초반)

`apps/web` 이나 `packages/*` 가 아직 없다면 관통 시나리오를 돌 수 없다.
그때는 **`docs/PLAN.md` 의 다음 미완료 행 하나**가 이번 바퀴의 일이다. 1번을 건너뛰고 3번으로 간다.

⚠ 「관통이 안 되니까」를 핑계로 PLAN 을 앞질러 여러 Phase 를 한 바퀴에 하지 마라.
**한 바퀴에 PLAN 한 행.** 그 행의 완료 기준을 만족시키는 것이 그 바퀴의 성과다.

### 1. 관통시켜 본다 (`import → publish → sync`)

```powershell
powershell -ExecutionPolicy Bypass -File tools/walkthrough.ps1
```

- 픽스처(`fixtures/paylab-*`)를 넣고 → 항목 구조화 → 충돌 카드 → 발행 → Pack 생성 →
  플러그인 `sync` → `applied` 보고까지 **실제로 지난다**
- 도중에 막히면 거기서 멈추고 **어디서 왜 막혔는지**를 낸다
- 결과: `.ci/walkthrough.json` · 화면 캡처 `.ci/shots/*.png`

### 2. **산출물을 눈으로 읽는다** — 이게 이 바퀴의 본체다

숫자는 「막혔나」까지만 말한다. **「믿을 만한가」는 산출물이 말한다.**

| 종류 | 무엇 | 어디서 보나 |
|---|---|---|
| **고장** | 진행이 막히거나 어긋난 것 | walkthrough 가 멈춘 자리 · 500 응답 · 해시 불일치 |
| **구멍** | 있어야 할 게 없는 것 | Pack 에 역추적 태그(`<!-- ctx:… -->`)가 없는 줄 · 근거 없는 항목 · 빈 화면 상태 |
| **격차** | 있긴 한데 초라한 것 | 화면이 `DESIGN_BRIEF.md` 토큰을 안 따름 · loading/empty/error 상태 없음 |

**Pack 을 열어 직접 읽어라.** 생성된 `CLAUDE.md` 를 사람이 읽었을 때
「이걸 우리 팀 규칙이라고 배포해도 되겠다」 싶은가. 아니면 그게 이번 바퀴의 일이다.

### 2-B. **정의만 있고 아무 일도 안 하는 것**을 찾는다

이런 저장소의 **단골 고장**이다 — 타입은 있는데 아무도 안 읽고, 필드는 있는데 늘 빈 값이다.
한 바퀴에 **두셋씩** 돌아가며 확인한다. 확인은 **두 단계**이고 첫 단계만으로 끝내지 마라:

| 단계 | 무엇 | 어떻게 |
|---|---|---|
| ① 소비처가 있나 | 그 이름을 **읽는 코드**가 있나 | `grep -rn "<이름>" packages apps plugin` — 타입 선언·표시용 코드는 **빼고** 센다 |
| ② 실제로 바꾸나 | 값을 바꾸면 **결과가 달라지나** | 테스트에서 그 값만 뒤집고 출력이 갈리는지 본다 |

이번 라운드의 후보 (돌아가며): `ItemType` 10종 · `SourceRef` 4종 · 에러 코드 9종 ·
sync 상태 5종 · `confidence` 3단계 · `scope.kind` 3종 · `enforcement` 4종.

죽은 것을 찾으면 **둘 중 하나만** 해라 — 어중간하게 두지 마라:
- **살린다** — 어디서 읽을지 정하고 배선한 뒤, 「이 값을 바꾸면 결과가 달라진다」를 시험으로 잠근다
- **지운다** — SPEC 의 표에서도 지우고, 왜 지웠는지 커밋 메시지에 한 줄 남긴다

### 3. 대장에 적고 **하나만** 고른다

찾은 것을 **`docs/feedback/FINDINGS.md`** 의 「다음에 고칠 것」에 심각도 순으로 적는다.

#### 🔴 무엇을 고를 것인가 — **PLAN 이 먼저다** (2026-09-05 규칙 변경)

```
① 고장(진행 불가)이 있으면  → 그것부터. PLAN 보다 위다
② PLAN 에 `- [ ]` 가 남아 있으면 → **PLAN 맨 위 행.** FINDINGS 는 건드리지 마라
③ PLAN 이 다 닫혔으면      → FINDINGS 맨 위(구멍 → 격차 순)
```

★ **왜 바뀌었나 — 실측이다.** 24바퀴(약 $250)를 돌리는 동안 `PLAN` 은 10/19 에서
**한 칸도 안 움직였다.** 그 사이 FINDINGS 는 89 → 102 로 늘고 70개가 닫혔다.
품질 작업 자체는 옳았지만, **하나 고치면 하나가 새로 나온다.** 눈으로 화면을 보는 한
격차는 무한히 나오므로, 「FINDINGS 맨 위가 늘 PLAN 보다 위」인 옛 규칙에서는
**PLAN 이 영원히 안 나간다.** 제출일이 있는 프로젝트에서 이건 조용한 실패다.

⚠ **`구멍`·`격차` 는 PLAN 을 막지 않는다.** 적어 두되 고르지 마라 —
그 항목의 **주인이 될 PLAN 행**을 적어 두고 그 행을 할 때 같이 닫는다.
⚠ `고장` 만 예외다. **진행이 막히는 것**(관통이 FAIL · CI RED · 500 응답)만 고장이다.
「초라하다」·「없다」는 고장이 아니다 — 그건 격차·구멍이고 ② 로 간다.

⚠ 순서는 **고장 → 구멍 → 격차**다. 발행이 막히는데 랜딩을 예쁘게 만들어 봐야
아무도 그 화면까지 못 간다.

고친 항목은 지우지 말고 `✅` 와 커밋 해시를 적는다 — 다음 바퀴가 **이미 본 것을
다시 찾느라** 한 바퀴를 통째로 쓰지 않게.

⛔ **할 일이 떨어졌다고 멀쩡한 코드를 리팩터링하지 마라.** 그게 자율 루프의 최대 실패 모드다.
큐가 비면 1번(관통)을 다시 돌려 **새로 찾는 것**이 그 바퀴의 성과다. 없으면 「없다」고 적어라.

### 4. 만든다 → 검사 → 커밋 → 다시 관통

4. **만든다** — 하나만. SPEC 의 해당 § 을 먼저 읽고.
5. **검사** — `powershell -ExecutionPolicy Bypass -File tools/ci.ps1` (결과는 `.ci/result` 한 줄)
6. **커밋** — 검사를 통과하면 **화면을 보기 전에 일단** (⑤ 참고)
7. **다시 관통** — 고친 것이 실제로 산출물에서 보이는지 확인한다.
   ⚠ **검사 초록은 「안 죽었다」지 「고쳐졌다」가 아니다.** 못 봤으면 `STATUS.md` 에
   「눈 판정 대기」로 적어라
8. **`docs/STATUS.md` 갱신** — 다음 바퀴의 유일한 기억이다.
   🔴 **다음 할 일은 머리의 한 줄로만 적는다** — `**다음 바퀴의 일 — FINDINGS <번호>**`
   (대기가 없으면 「FINDINGS 없음」). 그 번호는 FINDINGS 에서 **대기**여야 하고,
   `ci.ps1` 의 `docs` 층이 그걸 센다. ★ 왜 — 이 파일에 「다음 할 일」 자리가 둘이 됐던 적이
   있고, 손이 안 닿는 아래쪽 자리가 **두 바퀴 전에 닫힌 항목**을 계속 가리켰다 (FINDINGS 102).
   그리고 `### 지난 바퀴 (N)` 이 상한을 넘으면 제일 오래된 것을 **`docs/history/cycles.md`
   맨 위로 옮긴다** (베끼지 마라 — 게이트가 양쪽에 있는 것을 잡는다).
   **한 일이 아니라 잰 것을 써라.** (「API 작업함」 ✗ / 「publish 409 재현 테스트 3개 초록,
   Pack 파일 6개 생성, manifest_hash 고정」 ○)

powershell -ExecutionPolicy Bypass -File tools/ci.ps1

→ `.ci/result` 한 줄. **전 층이 초록이어야** 커밋한다.

### 🔴 CI 를 **백그라운드로 돌리지 마라.** 앞단에서 끝까지 기다려라

```
✗ 백그라운드로 띄우고 "알림이 오면 이어서 하겠다"      ← 세션이 그냥 끝난다
✓ 앞단에서 부르고, 끝날 때까지 기다렸다가 결과를 읽는다
```

★ **왜 — 이 세션에는 「다음 턴」이 없다.** 너는 `claude -p` 로 뜬 **한 번짜리
헤드리스 세션**이다. 백그라운드 작업의 완료 알림은 **다음 턴에** 오는데,
네가 「기다리겠다」고 말하고 턴을 끝내면 **그 턴이 마지막 턴이라 알림이 올 자리가 없다.**
세션은 조용히 종료되고, 고쳐 놓은 코드는 **커밋 안 된 채로** 워킹트리에 남는다.

★ **실측 2026-09-06** — 바퀴 2·3·4 가 연달아 이렇게 죽었다. 결과 줄에 남은 말이 그대로다:
> *"I'll wait for the CI notification before touching any files"*
> *"I'll hold until the CI notification arrives"*

세 바퀴가 커밋 0개로 끝나 **「빈 바퀴 3연속」 안전장치가 루프를 세웠다.**
바퀴 2 는 결함 ②(오류 로그)를 **실제로 다 고쳐 놓고도** 커밋을 못 했다.

⚠ CI 는 몇 분 걸린다. **그 몇 분을 앞단에서 기다리는 게 맞다** — 바퀴 상한은 75분이다.
⚠ 같은 이유로 **어떤 검사도 「띄워 놓고 나중에 확인」 하지 마라.**
  긴 명령은 앞단에서 끝까지 돌리고, 정말 오래 걸리면 **그 바퀴에서 범위를 줄여라.**

| 층 | 무엇을 보장하나 | 빨개지면 |
|---|---|---|
| `principles` | P1·P2·P3·P4·P6 을 기계로 센다 (`tools/principles.ps1`) | **제품의 주장이 깨졌다. 최우선이다** |
| `typecheck` | `tsc --noEmit` 전 패키지 | 타입이 갈렸다 |
| `test` | vitest — schema · compiler golden · api | golden 이면 ⑤ 의 규칙을 읽어라 |
| `build` | `next build` | 배포가 막힌다 |
| `walkthrough` | 관통 시나리오 (있을 때만) | ④1 로 돌아간다 |
| `docs` | 🔴 **`STATUS.md` 가 자기와 어긋나지 않는가** (`tools/status-shape.mjs`) — 다음 할 일을 말하는 자리가 **하나**이고 그 항목이 **대기**인가 · 지난 바퀴 기록이 상한 안인가 | ④8 을 안 했거나 반만 했다 |

**같은 지적이 두 번 나오면 규칙이 아니라 게이트로 올려라.** ③ 에 적는 것으로 끝내지 말고
